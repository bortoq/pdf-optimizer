# Архитектура pdfopt

## Поток данных

```
исходник ──► открыть (pikepdf) ─► подпись/шифрование? ─► Skipped
                │
                ├─► Fingerprint (страницы, content-хэши, метаданные)
                └─► метка /PdfOpt? ─► «уже оптимизирован»

lossless.build ──► [миниатюры, дедупликация] ─► [картинки] ─► [JPEG] ─► [ECT] ─► save
      │                                                                      │
      └── проверка: Fingerprint + пиксельное совпадение изменённых страниц ──┘
                │ не прошла → повтор без преобразований картинок
                ▼
           этап «lossless» (кандидат; в lossy — основа для следующих)
                │
   -q ──────────┼──► MRC ──► (страницы прошли SSIM) ──► + JPEG ──► кандидаты
                ├──► Ghostscript ×3 профиля
                └──► Hyper Compress

кандидаты по возрастанию размера ─► первый прошедший проверку ─► метка ─► os.replace
```

Каждый этап работает над одним открытым `pikepdf.Pdf`: файл разбирается один
раз, сохраняется один раз. Лишние движки прежней версии (`pypdf`, `qpdf`,
`jpegtran`, `pypdf+qpdf`, `pypdf+jpegtran`) заменены одной цепочкой, где проходы
складываются.

## Проверка

Принцип: **ни один кандидат не попадает в файл без проверки**, причём
проверяется только то, что реально могло измениться.

- `pdfmodel.Fingerprint` — MediaBox/CropBox/Rotate/число аннотаций и SHA-256
  декодированных content stream'ов каждой страницы. Lossless-проходы и MRC/JPEG
  не трогают content stream, поэтому сравнение байтовое и мгновенное. Извлечение
  текста (`pypdf`, медленное) нужно только когда content изменился (Ghostscript,
  Hyper) и вычисляется лениво.
- `render.identical_pages` — пиксельное совпадение 100-dpi отрисовки страниц с
  преобразованными картинками (RGB→Gray, 8→1 бит, JBIG2 generic, предикторы).
  При отказе повторяется сборка без преобразований картинок.
- `render.VisualGate` — SSIM 200-dpi отрисовки против эталона. Эталон
  рисуется один раз (PNG, параллельно кусками по 8 страниц) и общий для всех
  кандидатов; кандидат рисуется кусками и сравнивается сразу, первая плохая
  страница останавливает проверку (`stop_early`).
- `ssim.ssim` — окна 8×8 с шагом 4, как в `ffmpeg -filter ssim`; совпадает с
  ffmpeg до 6 знаков (тест `test_matches_ffmpeg`).

## Lossless-проходы (`lossless.py`)

| Проход | Идея | Гарантия |
| --- | --- | --- |
| миниатюры | `/Thumb` восстанавливается просмотрщиком | метаданные страниц не затронуты |
| дедупликация | потоки с одинаковыми байтами и словарём → одна ссылка | идентичные данные |
| картинки | RGB(R=G=B)→Gray, {0,255}→1 бит, PNG-предиктор, G4/Flate→JBIG2 generic | пиксельное совпадение отрисовки |
| JPEG | `jpegtran -optimize [-progressive]` | декодированные пиксели сравниваются |
| ECT -9 | пересжатие Flate встроенным компрессором (`pdfopt/_ect`, GIL отпускается, потоки масштабируются по ядрам); бюджет 256 МБ несжатых данных на документ | Deflate — без потерь |
| сохранение | object streams + xref streams (qpdf) | — |

Картинки читаются в главном потоке (объекты qpdf не потокобезопасны), а
кодируются в пуле потоков окнами по `2·jobs` штук, чтобы ограничить память.

## MRC (`mrc.py`)

1. `scan_candidates` — страницы ровно с одной картинкой (8 бит, Gray/RGB, ≥500 px,
   без масок и `/Decode`). Одинаковые картинки на разных страницах слоятся один
   раз, слои разделяются.
2. `ink_mask` — бумага оценивается по уменьшенной копии (макс. фильтр + размытие),
   чернила — пиксели, темнее бумаги более чем на `max(30, 30 %)`; полярность
   определяется по медиане (светлый текст на тёмном). При ≥250 dpi маска
   сглаживается голосованием 3×3 (≥5 из 9): уходят одиночные точки и рваные
   края, больше букв совпадает в словаре JBIG2.
3. `background_image` — страница при целевом разрешении; пиксели под чернилами
   заполняются нормализованной сверткой соседей (без ореолов).
4. `_background_search` — 100 dpi → (при успехе) 50 dpi, при неудаче — 200 dpi;
   качество JPEG — бисекцией по SSIM «превью» (композит фон+маска на 200 dpi) с
   запасом `PREVIEW_MARGIN`; JPEG 2000 пробуется при наличии `opj_compress`,
   от сильного сжатия к слабому (`JPX_RATES`, 2000:1 … 50:1). На почти плоском
   фоне JPEG не бывает меньше ~4 КБ/стр, JPEG 2000 — около 1 КБ.
5. `_foreground` — один цвет на страницу; если у тёмных ядер букв несколько
   цветов — палитра (`_palette_inks`): цвет считается по ячейкам 1/40 дюйма
   (тёмная половина чернил ячейки), краски различаются в основном по
   цветности (светлота с весом 0,35: тонкие штрихи светлее), до 6 красок,
   голосование 3×3 по ячейкам; каждая краска — своя маска со своим `rg`.
   Если ячейки далеко от палитры (90-й перцентиль > `PALETTE_FIT`) или краска
   одна — цветная картинка 25 dpi, рисуемая через маску.
6. Маска: JBIG2 с общим словарём на 64 маски (`-s`), если суммарно меньше
   Group 4/Flate; `--safe-text` — generic JBIG2 без словарей. Порог совпадения
   символов — по размеру букв (`stem_height`: 90-й перцентиль вертикальных
   серий чернил, px): ≥15 → 0,80, ≥12 → 0,85, ≥10 → 0,90, иначе generic
   без потерь (`JBIG2_THRESHOLDS`, `JBIG2_LOSSLESS`). Безопасного порога для
   глифов меньше 10 px нет: на 14 px (3,5 pt) даже `-t 0.92` дало 333 подмены
   9→8, `-t 0.90` — 410. Пороги не выше 0,9, потому что jbig2enc 0.28
   (Ubuntu 24.04) отвергает большие значения, а символьный режим тогда не
   работает вовсе; его порог по умолчанию — 0,85, поэтому `-t` передаётся
   всегда.
   Размер меряется по полосам строк между пустыми строками (`size_classes`),
   и маска каждой краски делится на части по порогу: сноска под обычным
   текстом получает свою маску со строгим порогом. Маски с одним порогом
   кодируются вместе, чанками с общим словарём. 0,80 вдвое-втрое уменьшает
   маску по сравнению с 0,92 и даёт размер на уровне `cjb2 -lossy`.
   Границы сняты на случайных цифрах с размытием и шумом при 300 dpi
   (декодированный глиф классифицируется по усреднённым шаблонам): на 5 pt
   `-t 0.80` дало 62 подмены 6→8, на 4 pt `-t 0.85` — 34 подмены 8↔6. Строки
   из одних цифр 5 pt меряют 13 px и при 0,80 ещё путались — отсюда запас.
   С выбранными порогами подмен не было ни на одном размере, в том числе в
   сносках 4–6 pt под текстом 10 pt; разбиение стоит ~5 % размера.
7. Порог страницы: если задан `relaxed` (`--mrc-quality`) и страница
   `text_like` — в каждом тайле 128 px с чернилами композит «оригинал как
   фон + маска» держит SSIM ≥ 0,85 (у текста ~0,92, у огрублённой фотографии
   ~0,6) — страница проверяется по `relaxed`, иначе по основному порогу.
8. `build` — слои пишутся в Form XObject (`/PdfOptLayers`), страница
   сохраняется, `VisualGate` проверяет каждую страницу по её порогу, не прошедшие
   возвращаются (`restore`), документ сохраняется снова.

Страницам даются собственные словари ресурсов (копии), так что общие/унаследованные
`/Resources` соседних страниц не затрагиваются.

## Lossy JPEG (`jpegopt.py`)

- `effective_dpis` разбирает content stream (стек `q`/`Q`/`cm`) и находит dpi,
  с которым каждая картинка показана.
- `reencode` — для масштабов {1.0, 300, 225, 150 dpi} бисекцией ищет наименьшее
  качество, при котором SSIM *в разрешении проверки (200 dpi)* не ниже
  `порог + SEARCH_MARGIN`; выигрывает наименьший по байтам; победитель
  пересобирается baseline/progressive (и mozjpeg, если есть) с тем же
  результатом пикселей.
- Модель отрисовки повторяет poppler: уменьшение — усреднение по площади (BOX),
  увеличение — повтор пикселей (NEAREST, до 4×); картинки с dpi ниже 200
  оцениваются увеличенными, иначе SSIM их не видел бы блочность.
- `optimize._Run.jpeg_stage` проверяет страницы с перекодированными картинками
  реальной отрисовкой; картинки страниц, не прошедших порог, возвращаются
  (`jpegopt.revert`), остальные остаются.
- Flate-картинки с ≥1500 цветов в выборке считаются фотографиями и переводятся в
  JPEG; графика остаётся в Flate.
- Формы, созданные MRC, пропускаются — слои не перекодируются дважды.

## Параллелизм

- Между файлами: `ProcessPoolExecutor`, на файл приходится `ядра // файлов`; число ядер определяется автоматически.
- Внутри файла: MRC — процессы (`_bounded_map` держит не более `2·jobs` страниц в
  памяти), картинки и рендеринг — потоки (тяжёлая работа в `numpy`, `zlib`,
  `pdftoppm`, не держащих GIL), ECT — потоки.
- При `jobs ≥ 4` независимые движки (MRC, Ghostscript, Hyper) идут одновременно;
  каждому — свой подкаталог `scratch`.

## Решения и ограничения

- **SSIM слеп к деталям мельче 200 dpi** и усредняется по странице, в основном
  белой. MRC дополнительно держит запас `PREVIEW_MARGIN` и проверяет реальную
  отрисовку. Символьный JBIG2 может склеить похожие буквы; порог по размеру
  букв защищает от этого на проверенных размерах, но SSIM подмену не видит —
  для критичных документов `--safe-text`. Refinement (`jbig2 -r`, «мягкое»
  сопоставление, которое исправляет подмены) не используется: по README
  jbig2enc такие файлы роняют Acrobat. OCRmyPDF по той же причине убрал
  lossy JBIG2 совсем.
- **Превью — модель отрисовки poppler.** На масштабируемых страницах (обычный
  скан 300 dpi → 200 dpi) оно ошибается не больше чем на ±0,004 SSIM, в запасе
  `PREVIEW_MARGIN`. Заметно (до +0,025) оно переоценивает только цветной текст
  на странице 1:1: poppler иначе восстанавливает цветность JPEG, и разница
  сидит в отрисовке самой маски. Такая страница не проходит строгий порог и
  остаётся картинкой (по порогу текста — проходит). Проверено и отвергнуто:
  рендер poppler как эталон превью (смешивает модели масштабирования, ошибка
  на сканах вырастает до −0,07) и повтор отклонённых страниц с целью,
  поднятой на измеренную ошибку (фон эту ошибку не компенсирует).
- **Метка `/PdfOpt`** хранится в Catalog, а не в Info, чтобы не нарушать проверку
  метаданных в lossless. Файл, не получивший экономии, метки не получает и будет
  разбираться заново.
- **Не обрабатываются:** шифрованные и подписанные PDF, CMYK/Indexed JPEG и
  картинки с `/Decode` и цветовыми масками в lossy, inline-изображения, картинки
  внутри форм при определении dpi.
- **Диск:** рабочий каталог создаётся рядом с файлом (для атомарной замены);
  для `-q` эталонные отрисовки занимают порядка 1 МБ на страницу.
- **Память:** страницы MRC декодируются целиком (≈25 МБ на страницу 300 dpi A4 в
  numpy-массивах, несколько копий); при `-j` больше числа ядер выигрыша нет.
